## Core Thesis

AI governance is not a policy document that sits on a shelf.

It is the operating system that defines what AI can access, who can use it, how outputs are reviewed, which vendors are approved, and what happens when risk or uncertainty appears.

## Recommended Structure

### What Governance Should Answer

- which AI systems are approved?
- which data classifications may be used?
- who has access?
- which workflows require human review?
- which use cases are prohibited?
- how are vendors evaluated?
- how are incidents handled?
- how are systems monitored?

### Data Classification

Possible categories:

- public
- internal
- confidential
- customer-sensitive
- regulated/restricted

Use organization-specific policy rather than universal assumptions.

### Access Controls

Discuss:

- role-based access
- least privilege
- authentication
- data permissions
- system boundaries
- logging where appropriate

### Human Review

Define where approval is required before AI-assisted output becomes an action.

### Vendor Review

Consider:

- data handling
- retention
- training-use policies
- security posture
- contractual terms
- deployment model
- integration access

### Monitoring

Governance should evolve with:

- new use cases
- new models
- changing systems
- incidents
- business changes
- policy updates
